# Opportunity Facts

Opportunity Facts turns public pages about student opportunities into standardized, source-backed facts cards. The primary experience is the URL analyzer: paste an opportunity page, watch observable research and validation milestones, and receive a practical evidence-backed draft. Students and families can then inspect evidence, compare opportunities, or export their work without creating an account.

The product reports what reviewed sources disclose. It does **not** rate legitimacy, quality, prestige, admissions impact, or value, and it does not independently audit an organizer's claims. `not_found`, `unclear`, and `conflicting` are intentional results.

The bundled dataset contains ten independently researched, AI-audited real cards and seven clearly labeled fictional `.example` demos. A separate AI-assisted audit checked source/value/excerpt alignment for those ten records; no person has yet completed their full review. This is not organizer endorsement or independent legitimacy auditing.

All repository cards use schema `2.2.0`. It retains Schema `2.1.0` educator-recipient safeguards and adds explicit automated-draft and AI-audited provenance; schema `2.0.0` and `2.1.0` imports preserve rich claims and evidence while rebuilding their summary under current projection rules. The 59-field facts map remains the stable summary/comparison surface, while evidence-bearing structured records preserve cycle identity, multiple organizations, tiered prices, stage/pathway differences, and outcome scope without flattening them into misleading scalars.

## Architecture

Opportunity Facts is a Next.js App Router application with strict TypeScript, React, Tailwind CSS, Zod, Vitest, and Playwright. It does not require a database.

- `lib/opportunity/schema.ts` exports the authoritative schema `2.2.0` contract. `schema-version.ts`, `schema-v2.ts`, `structured-schema.ts`, `projection.ts`, and `migration.ts` enforce versioned structured evidence, deterministic 59-field projections, conservative V1 migration, and lossless `2.0.0`/`2.1.0` import; `registry.ts` retains exactly 13 core assessment areas.
- Repository JSON powers public demo and reviewed cards. Browser storage holds only user-requested drafts and comparison selections.
- Server-side URL acquisition validates DNS and every redirect, connects to the validated address, limits content type/time/bytes, and discovers at most six relevant links from the submitted origin. One ranked application link may follow one revalidated public cross-origin redirect to a third-party form; every later redirect is pinned to that form origin.
- HTML is reduced to normalized, non-executable text. Source-page instructions are treated as hostile data.
- Normal Analyze uses one compact strict-output Responses request. It asks only for sparse, decision-useful semantic claims, carries source metadata once, caps model source text at 55,000 characters and output at 4,800 tokens, and lets deterministic code hydrate evidence, resolve cycle context, validate semantics, and assemble the Overview. It does not ask the model to fill all 59 storage fields or generate rich ledgers by default.
- Optional **Extended Research** reuses the normal result and the exact acquired source contexts through a bounded, opaque, 30-minute server session. Two independently salvageable requests then examine detailed process/relationships/terms and financial/outcome structure. A failed, cancelled, or partial extension never replaces the successful normal Overview.
- Every request uses low reasoning effort, low text verbosity, `store: false`, no automatic retry, and bounded input/output. Deterministic post-processing still rejects unsupported excerpts, wrong subjects/recipients, historical-cycle mixing, sibling-program evidence, typed-value mismatches, unsafe relationship/scope upgrades, and incomplete prize flattening.
- Analyzer results are split into a student-facing Overview and, after Extended Research or for repository examples, a research-record workspace. Needs Attention rows retain only grounded claim/status references, and a deterministic quality gate suppresses structurally unreliable cards without producing a trust score. The already-generated incomplete draft remains available behind an explicit amber override that performs no new model call.
- API analysis responses are marked `Cache-Control: no-store`. The shared store keeps eligible insufficient-quality classifications and fingerprints for 14 days, and temporarily retains the bounded acquired-source context plus validated normal result behind an opaque Extended Research session for at most 30 minutes. It does not retain source text after that continuation window. The application has no analytics or hidden telemetry.

See [`PROJECT_SPEC.md`](PROJECT_SPEC.md), [`docs/SCHEMA_AND_DATA.md`](docs/SCHEMA_AND_DATA.md), and [`docs/THREAT_MODEL.md`](docs/THREAT_MODEL.md) for the durable contract and security boundaries.

## Install and run

Prerequisites: Node.js 20.9 or newer and npm.

```powershell
npm ci
Copy-Item .env.example .env.local
npm run dev
```

Open `http://localhost:3000`. An OpenAI key is optional; samples, browsing, comparison, manual building, imports, exports, research, and methodology all work without it.

For a production-mode local run:

```powershell
npm run build
npm run start
```

## Adding a reviewed card

1. Run `npm run create:card -- <lowercase-kebab-case-slug>`.
2. Edit the new file in `data/drafts/` using only public sources and keep `reviewState: "draft"` while review is incomplete.
3. Inventory the opportunity/cycle separately, assess every structured collection, and attach evidence to each independently reviewable organization, role/scope, timing, cost, pathway, and outcome assertion. The builder generates mapped flat facts; do not edit V2 projections directly.
4. Attach an exact source excerpt to every displayed factual value. Preserve supported disagreements as conflicts; do not choose a preferred value or flatten tier/pathway differences.
5. Use `ai_audited` only after a separate AI-assisted audit checks value, excerpt, source, scope, projection, and structured-record alignment. Use `human_reviewed` only after a person independently performs the relevant checks. `organizer_confirmed` means supplied or confirmed by the organizer, not independently audited.
6. Complete [`docs/REVIEW_CHECKLIST.md`](docs/REVIEW_CHECKLIST.md), set a truthful reviewed state and timestamp, then move the file to `data/opportunities/`.
7. Run `npm run export:data`, `npm run validate:data`, and `npm test`. The exporter fails closed on drafts, stale projections, duplicate opportunity/cycle identities, or unassessed reviewed structures.

Schema V1 files may still be imported for recovery, but they always become draft V2 revisions. The migration preserves legacy facts and evidence, records a digest, clears review attestation, and requires manual structured review before publication.

The aggregate dataset is available at `/api/dataset` and `public/data/opportunities.json`; the machine-readable schema is available at `/api/schema` and `public/schema/opportunity-card.schema.json`.

## Analysis boundaries

- Only unauthenticated public HTTP(S) pages on protocol-default ports are accepted. Local, private, link-local, metadata/platform-service, credential-bearing, sensitive-query/fragment, non-default-port, and unsafe redirect destinations are rejected.
- Recognized marketing identifiers such as `utm_*`, advertising click IDs, and `attribution_id` are removed before fetching and before URLs become source metadata. Functional query parameters are preserved; token-, signature-, session-, auth-, and secret-like keys are rejected rather than stripped.
- A request has a 10-second fetch deadline, a 1.5 MB response limit, at most five redirects, and at most six discovered links selected from the submitted origin. Only one selected `application` link may cross origins, once, through a redirect; its destination is fully revalidated and all later redirects must remain on the new origin. Direct external links are never ranked. Only HTML and plain text are accepted.
- Static extraction cannot reproduce every client-rendered site, shadow DOM, computed visibility rule, or anti-bot flow. Paste-source mode is the fallback.
- Automated URL and paste analysis labels sources `user_supplied`; paths, branding, and same-origin discovery do not prove that a page is official.
- Model extraction can omit or misunderstand disclosures. Exact excerpt matching proves text presence, not truth, authority, or correct interpretation; drafts still require human review.
- The application rejects non-JSON and cross-origin browser analysis submissions, limits request bodies to 600 KB and ten seconds of read time, exposes a server-side kill switch, and applies a small per-process concurrency ceiling across body reading and analysis. These are defense in depth, not distributed rate limiting.
- The analyzer has a 270-second total application deadline inside its 300-second Next.js route envelope; disconnects and deadline expiry cancel downstream fetch/model work and release local admission capacity.
- Production refuses paid work unless the shared per-identifier rate limit, weighted global concurrency lease, and daily/total spend reservation can be enforced. Provider-side caps/alerts and outbound-network policy remain additional defenses.

## Privacy behavior

Submitted URLs and pasted text are processed transiently. When Extended Research is available, the bounded acquired-source context and validated normal result are held in the shared continuation store for no more than 30 minutes, then expire automatically. If model extraction is configured, normalized public source text is sent to OpenAI with `store: false`; provider and hosting logs remain governed by their respective account settings and policies. Remote sites and DNS resolvers observe fetches. Drafts and comparison selections persist locally only when the user asks to save or compare, and downloads persist wherever the browser or device stores them.

Application code does not log request bodies, prompts, fetched text, evidence
excerpts, authorization headers, or raw request addresses. Failure-suppression
checks carry the submitted opportunity URL in a bounded JSON body, not an access-log
query string.

## Deploying to Vercel

Import the repository as a Next.js project, keep the default build command (`npm run build`), and add only the environment variables needed for the deployment. Store `OPENAI_API_KEY` as a server-side secret and do not expose it to preview builds for untrusted changes. Keep analysis disabled until durable aggregate gateway rate/concurrency limits and a provider or gateway hard-spend circuit breaker are configured. The exact preflight and deployed checks are in [`docs/DEPLOYMENT_CHECKLIST.md`](docs/DEPLOYMENT_CHECKLIST.md).

No deployment is performed automatically by this repository.

## Project structure

```text
app/                    App Router pages and bounded API routes
components/             Facts card, comparison, builder, analysis, and correction UI
data/demo/              Seven fictional demo cards
data/drafts/            Private repository drafts excluded from public exports
data/opportunities/     Ten AI-audited public records
docs/                   Schema, review records, threat model, and release screenshots
lib/opportunity/        V2 schema, structured claims, projections, migration, registry, and serialization
lib/analysis/           URL safety, pinned fetching, extraction, model, and evidence pipeline
public/data/            Deterministic downloadable dataset
public/research/        Public copies of the research kit
public/schema/          Exported machine-readable schema
research/               Honest study and benchmark protocols/templates
scripts/                Card creation, export, and data validation
tests/                  Unit, integration, security, fixtures, and Playwright flows
```

The research page intentionally says **Study not yet published** until a consented comprehension study exists. The repository's development and out-of-sample extraction reports are engineering evaluations, not user-study or population-level accuracy claims. No users, organizer responses, or study results are fabricated.

The first live-provider extraction development benchmark is preserved locally in
[`EXTRACTION_BENCHMARK.md`](./EXTRACTION_BENCHMARK.md). It uses the three existing
then-labeled reviewed cards as a tuning set and is explicitly not independent or
out-of-sample accuracy evidence.

The subsequent [`OUT_OF_SAMPLE_EVALUATION.md`](./OUT_OF_SAMPLE_EVALUATION.md)
preserves one frozen production run on each of seven preregistered opportunities.
At this release, the public library contains ten independently assembled cards,
all still labeled AI-audited until a person completes the digest-bound review
workflow, plus seven clearly fictional demos. The evaluation found four critical
misleading automated claims, so automated output remains a draft requiring human
source review; it is not suitable for unattended publication.
